# Longhorn Messenger — протокол сервер↔клиент

Всё в JSON. REST + один WebSocket-эндпоинт. Сервер слушает `:8080` (флаг `-addr`).

## REST

Все ответы при ошибке: `{"error":"текст"}` с кодом 4xx. Авторизация: заголовок `Authorization: Bearer <token>`.

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| POST | `/api/register` | `{name, password, avatar}` | `200 {token, user:{id,name,avatar}}`; `409` имя занято; `400` валидация |
| POST | `/api/login` | `{name, password}` | `200 {token, user:{id,name,avatar}}`; `401` неверные данные |
| POST | `/api/logout` | — | `204` |
| GET | `/api/me` | — | `{user:{id,name,avatar,status,mood}}` |
| GET | `/api/users` | — | `[{id,name,avatar,status,mood,lastSeen,bot}]` без себя |
| GET | `/api/history/{uid}?before=N&limit=100` | — | `{messages:[...], hasMore}` |

Ограничения: имя 2–24 символа, уникально (без учёта регистра); пароль 4–64; `avatar` int 0..5; текст сообщения ≤ 4000 символов.

`/api/*` обязан отвечать на CORS preflight (`OPTIONS`) и слать `Access-Control-Allow-Origin: *` — клиент работает из Tauri (`tauri://localhost`) и браузера.

`GET /health` → `200 ok`.

## WebSocket

`GET /ws?token=<token>`. Неверный токен → close 4001. Новое подключение того же юзера закрывает старое.

Формат кадров: `{"type":"...", ...}`. Пинг/понг стандартные, сервер рвёт соединение через 60с тишины.

### Клиент → Сервер

```jsonc
{"type":"msg","id":"c1","to":2,"text":"привет"}       // id — клиентский, для ack
{"type":"typing","to":2,"on":true}
{"type":"read","to":2,"seq":41}                        // «я прочитал переписку с юзером 2 до seq 41 включительно»
{"type":"presence","status":"on|idle|dnd|inv","mood":"текст до 60 симв."}
{"type":"call","op":"offer","to":2,"callID":"abc","sdp":"..."}   // звонок (аудио)
{"type":"call","op":"offer","to":2,"callID":"abc","sdp":"...","renego":true}  // повторный offer внутри идущего звонка (видео)
{"type":"call","op":"answer","to":1,"callID":"abc","sdp":"..."}   // renego:true — аналогично для ответа
{"type":"call","op":"ice","to":2,"callID":"abc","cand":{"candidate":"...","sdpMid":"0","sdpMLineIndex":0}}
{"type":"call","op":"end","to":2,"callID":"abc"}       // завершили разговор
{"type":"call","op":"reject","to":1,"callID":"abc"}    // входящий отклонён
{"type":"call","op":"cancel","to":2,"callID":"abc"}    // вызывающий передумал (в т.ч. пока висит в очереди)
```

### Сервер → Клиент

```jsonc
{"type":"hello","me":{"id":1,"name":"G2961","avatar":5,"status":"on","mood":""},
 "users":[{"id":2,"name":"Алиса","avatar":0,"status":"on","mood":"...","lastSeen":1710000000,"bot":false}],
 "unread":{"2":3}}                                    // первое сообщение после коннекта
{"type":"presence","id":2,"status":"on|idle|dnd|off","mood":"...","lastSeen":1710000000}  // рассылка всем
{"type":"msg","from":2,"id":"s17","text":"привет","time":1710000000,"seq":17,"sys":false} // входящее (sys=true — служебное: пропущенный звонок и т.п.)
{"type":"sent","id":"c1","sid":"s18","time":1710000000,"seq":18}   // ack для отправителя
{"type":"typing","from":2,"on":true}
{"type":"read","by":2,"seq":18}                        // собеседник прочитал до seq 18 (мои сообщения с seq ≤ 18 — прочитаны)
{"type":"call","op":"offer","from":1,"callID":"abc","sdp":"...","note":""}   // входящий звонок
{"type":"call","op":"answer","from":2,"callID":"abc","sdp":"..."}
{"type":"call","op":"ice","from":1,"callID":"abc","cand":{...}}
{"type":"call","op":"end","from":2,"callID":"abc"}
{"type":"call","op":"reject","from":2,"callID":"abc"}
{"type":"call","op":"busy","from":2,"callID":"abc"}
{"type":"call","op":"cancel","from":1,"callID":"abc"}
{"type":"call","op":"queued","callID":"abc"}           // абонент оффлайн: звонок поставлен в очередь, прозвонит при его входе
```

## Семантика

### Присутствие (как в Discord)
- Статусы: `on` (в сети), `idle` (неактивен), `dnd` (не беспокоить), `inv` (невидимка).
- Своё真实 состояние юзер знает из `hello.me`; **остальным** `inv` рассылается как `off`. Реальный оффлайн тоже `off`.
- Клиент сам делает авто-idle (5 мин бездействия → `idle`, активность → возврат на ручной статус) и шлёт `presence`.
- При отключении сервер рассылает `presence` с `off` и обновляет `lastSeen`.

### Сообщения
- `seq` — сквозной возрастающий номер внутри пары (переписки), единый для обоих участников.
- `sent`-ack подтверждает доставку на сервер (клиент рисует ✓, до этого — часы).
- Прочитано: клиент, когда открыт/в фокусе чат, шлёт `read` с последним seq. Собеседник по `read.seq` помечает свои ✓✓.
- Оффлайн-доставка: сообщения пишутся в историю; при коннекте получатель видит их в `hello.unread` и подгружает историю.

### Звонки (WebRTC, сигналинг через сервер)
- `callID` генерирует вызывающий (случайная строка).
- Каждому юзеру один активный звонок; входящий второму звонящему → сервер отвечает `busy`.
- **Звонок оффлайн-юзеру разрешён**: сервер кладёт offer в очередь (`queued` вызывающему). Когда адресат зайдёт в сеть — ему доносится `offer` (у него звонит). Не ответил 45с → сервер всем пишет sys-сообщение «Пропущенный звонок» и чистит очередь.
- Отклонение/отмена/занятость (`reject`/`cancel`/`busy`) сервер логирует в переписку sys-сообщением обеим сторонам («Звонок отклонён», «Вы отменили звонок», «Абонент занят»).
- Разрыв WS в **разговоре** (answer уже был): звонок не гасится — медиа идёт P2P и не зависит от сигналинга (телефон свернули, WebView заморозили). Если участник не вернулся за 40с (grace-таймер), а второй тоже оффлайн — звонок завершается (`end` обеим сторонам + sys-строка). Реконнект того же юзера в grace продолжает звонок.
- Разрыв WS во время **дозвона** (answer не было) → мгновенный `end` второй стороне, как раньше.
- `offer`/`answer` с `renego:true` внутри идущего звонка (добавление видео/шеринга) — просто релеются второй стороне, не считаются новым звонком и не дают `busy`.
- Бот-юзеру звонить нельзя → `busy`.

### Служебные сообщения
Хранятся в истории пары как обычные сообщения с `sys:true` и `from` = инициатор события (для отображения). Клиент рисует их по центру курсивом.

### Эхо-бот
Юзер с флагом `bot:true` (создаётся сидом). На любое сообщение отвечает: шлёт отправителю `typing on`, через ~1с сообщение-эхо, `typing off`. Статус всегда `on`, звонки — `busy`.

JSON-файл (`-db data/db.json`, флаг `-seed` создаёт демо-юзеров при пустой базе: Алиса/Дима Билд/Хук-хук/Сергей/Катя + Эхо-бот, пароль у всех `demo1234`). Атомарная запись (tmp+rename), сохранение дебаунсом ~500мс и при завершении.
